# XLS SV32

SV32 is an [RV32I](https://riscv.org/) core implemented in DSLX and built
with the official [Google XLS](https://github.com/google/xls) toolchain. This
repository is a testbed for using XLS on real RTL: DSLX is type-checked and
simulated with the XLS interpreter and LLVM JIT, lowered to optimized IR,
emitted entirely by XLS as a clocked Verilog core with explicit memory ports,
and simulated with Icarus Verilog against an independent Python reference model.
Altera Quartus Prime Pro synthesizes, fits, checks timing, and assembles the
DE25-NANO FPGA programming image.

The design is documented in [docs/sv32.md](docs/sv32.md).
The complete blinky SoC and DE25-NANO board flow are documented in
[docs/soc.md](docs/soc.md).
Current findings and the ordered roadmap, starting with the physical blinky
test, are tracked in [TODO.md](TODO.md).

Add hardware designs under `src/<design>/`, verification code under
`tests/<design>/`, and notes under `docs/`. Build scripts place generated
files under `build/<design>/`. Commit source, tests, scripts, launchers,
configuration, and documentation; keep downloaded binaries, archives, and
generated output out of Git. `.gitignore` excludes `tools/`, `downloads/`,
and `build/` rather than all `.v`/`.x` files, so hand-written HDL and test
fixtures can still be versioned.

## Install the toolchain

The supported host platform is Linux x64. The binary XLS release pinned in
`config/tools/xls-install.json` is installed locally; no Bazel or source build
is required:

```bash
./scripts/install-xls.sh
```

The script downloads into a temporary file and caches the archive only after
its SHA-256 digest matches the manifest. It repairs corrupt cache entries and
incomplete installations, validates a staged installation, then refreshes
`tools/xls`. Failed downloads or extraction leave a working default link intact.

`bin/xls` launches any installed XLS executable directly. Relative paths
resolve from the project root:

```bash
./bin/xls interpreter_main --version
./bin/xls interpreter_main --dslx_path=src/sv32 \
    tests/sv32/sv32_test.x
```

FPGA builds require Altera Quartus Prime Pro with Agilex 5 device support.
Put `quartus_sh` on `PATH`; `build-de25.py` locates the accompanying Platform
Designer tools from that installation. RTL simulation requires Icarus Verilog
(`iverilog` and `vvp`).

C firmware uses `riscv32-unknown-elf-gcc` and the matching binutils on `PATH`.
They are installed under `/opt/riscv/bin` on this host. The build selects
`-march=rv32i -mabi=ilp32` for the current core and supplies its own startup
and linker script.

## Generate and test the core

```bash
python3 scripts/build-sv32.py     # DSLX -> IR -> clocked core + wrapper
python3 scripts/test-sv32.py      # DSLX tests, RTL build, and simulation
python3 -m unittest discover -s tests/sv32 -p 'test_*.py' -v  # Core/wrapper builds
```

`test-sv32.py`:

1. Runs the DSLX unit tests with the interpreter and compares results with
   the LLVM JIT (23 tests across ALU, branches, jumps, memory, and decoding).
2. Converts the `sv32_core` DSLX proc to XLS IR, adapts its channels to
   single-value memory/debug ports, and optimizes it.
3. Uses XLS's one-stage proc codegen to generate all of `sv32_core.v`, including
   the PC and register-file storage, asynchronous reset, and memory ports.
   `sv32_top.sv` is a wiring-only compatibility wrapper.
4. Simulates 35 programs with Icarus Verilog and compares every register,
   data-memory word, halt PC, and cycle count against `tests/sv32/sv32_ref.py`.
   Directed expectations also check reset writes, halfword lanes, shift counts,
   and unsupported encodings independently of the reference interpreter.

To simulate an existing build without rerunning the DSLX checks:

```bash
python3 scripts/test-sv32.py --simulate-only build/sv32
```

The quicker smoke test skips simulation and only checks the XLS flow:

```bash
./bin/run-smoke-test.sh
```

Installer regression tests run offline in temporary projects:

```bash
python3 -m unittest discover -s tests/tools -p 'test_install_xls.py' -v
```

With the RISC-V compiler available, test the firmware linker guards with:

```bash
python3 -m unittest discover -s tests/tools -p 'test_firmware.py' -v
```

## Run the blinky SoC

The synthesizable SoC contains 1 KiB of instruction ROM, 1 KiB of data RAM,
and an LED register at `0x10000000`. The firmware keeps its blink counter in
RAM and toggles the LED every 0.5 seconds at 100 MHz.

```bash
python3 scripts/build-soc.py              # Hardware ROM image and core
python3 scripts/test-soc.py              # RTL, memory/MMIO, and board tests
python3 scripts/build-de25.py --compile  # DE25-NANO Quartus build (100 MHz)
```

The DE25-NANO project uses the board's 50 MHz oscillator, a generated 100 MHz
PLL, configuration reset release, KEY0 reset, and active-low LED0. The Quartus
project is generated under `build/de25_nano/`. Load
`build/de25_nano/output_files/sv32_de25_nano.sof` with Quartus Programmer
and the onboard USB-Blaster III. See
[docs/soc.md](docs/soc.md) for the address map, waveform files, and programming
instructions.

To build and run the C version, use `--firmware c`. The existing Python
instruction generator remains the default:

```bash
python3 scripts/build-firmware.py         # Standalone C ELF, binary, hex, and disassembly
python3 scripts/test-soc.py --firmware c --output-dir build/sv32_soc_c_test
python3 scripts/build-de25.py --firmware c --seed 2 --output-dir build/de25_nano_c --compile
```

The C programming image is `build/de25_nano_c/output_files/sv32_de25_nano.sof`.
Its ROM startup initializes the stack and clears BSS before calling `main`.
See [the C firmware notes](docs/soc.md#compiled-c-rom-firmware) for the current
Harvard-memory limitations and bootloader requirements.

## The core as a DSLX proc

`src/sv32/sv32_core.x` owns the PC and register file as proc state, initializes
both to zero, and calls the pure instruction function in `src/sv32/sv32_execute.x`:

```text
step(state, imem_rdata, dmem_rdata) -> (state', dmem_req, halt)
```

XLS generates the complete core RTL from this proc, including state storage.
The build uses one pipeline stage with unregistered I/O, preserving single-cycle
execution and combinational memory reads. A small IR adapter selects
single-value channels because the pinned DSLX frontend emits streaming channels;
it does not add logic or edit generated Verilog. See [docs/sv32.md](docs/sv32.md).

The public `sv32_core` module uses the following interface:

| Signal | Direction | Width | Purpose |
| --- | --- | --- | --- |
| `clk`, `rst_n` | in | 1 | Rising-edge clock and asynchronous active-low reset |
| `reset_n` | in | 1 | DSLX store-suppression reset; connect to the same signal as `rst_n` |
| `imem_addr` | out | 32 | Instruction fetch byte address |
| `imem_rdata` | in | 32 | Instruction word at the current PC |
| `dmem_addr` | out | 32 | Word-aligned data byte address |
| `dmem_wdata` | out | 32 | Store data positioned in byte lanes |
| `dmem_wstrb` | out | 4 | Byte write enables |
| `dmem_rdata` | in | 32 | Data word at the emitted address |
| `halted` | out | 1 | Halt flag |
| `debug_pc` | out | 32 | Current PC |
| `debug_regs` | out | 1024 | Optional register-file observation |

The core holds its PC and 32 registers internally and freezes them on halt, so
`ECALL`/`EBREAK` and unsupported encodings stop without committing effects.
Store strobes are suppressed during reset. The `debug_regs` output can be left
unconnected; register `xi` occupies `[32*i +: 32]`. Memories must provide
combinational reads, with stores accepted at rising clock edges.

`sv32_core.v` is the direct, unmodified XLS codegen output; there is no
hand-written state-storage shell or separate datapath module. Connect both
`rst_n` and `reset_n` to the same reset signal. `sv32_top` preserves the original
single-reset interface by making that connection internally. The SoC and board
surroundings remain Verilog. See [docs/sv32.md](docs/sv32.md) for ISA coverage,
the memory model, and verification details.

## Toolchain notes

- `config/tools/xls-install.json` pins the XLS release URL, platform, size,
  and checksum.
- Altera Quartus Prime Pro handles FPGA synthesis, fitting, timing analysis,
  and `.sof` assembly through `scripts/build-de25.py --compile`.
- Icarus Verilog (`iverilog`/`vvp`) is required for RTL simulation.

Upstream references: [XLS installation](https://github.com/google/xls#install-latest-release),
[XLS tool quick start](https://google.github.io/xls/tools_quick_start/), and
the [RISC-V unprivileged ISA specification](https://riscv.org/technical/specifications/).
